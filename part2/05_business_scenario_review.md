# 业务场景与模型一致性审查

日期：2026-11-17。以下为静态设计走查，检查预期业务结果与模型、正文是否一致；没有执行产品测试或用户实验。

| 场景 | 预期结果与设计依据 | 本轮走查结论 |
|---|---|---|
| 花生过敏，仅输入“番茄鸡蛋面”，无配料 | 名称无法排除隐藏配料；受影响推荐进入待核对；M04、ADR-06 | 目标模型明确；当前餐名过滤列为 GAP-02 |
| 行动提出“加一份水果”，水果未确认 | 对新引入食物重查约束与可获得性；不得只验证原餐 | 第 03 章 GAP-02、第 04 章流程已覆盖 |
| 两人备餐，番茄每人 150g，库存确认 100g | 总需求 300g，需购 200g；保存计划不扣库存 | 多食材行、人数基准及 M05 已覆盖 |
| 面条总需求 200g，但库存未核对 | 需购未知；不是默认购买 200g 或按零库存确定差额 | 第 04 章数量规则、GAP-04 已覆盖 |
| 周计划只选工作日午餐 | 显示指定餐次模式；全餐模式则报告缺项，不造餐补齐 | 数量规则定义模式；作为 CHG-07 记录语义细化 |
| 预填两人午餐，用户实际吃一碗、份量未知 | 只预填名称与引用；个人数量 null；确认后才保存实际记录 | M05 与 GAP-08 已覆盖 |
| 已采纳“换白水”，保存了一条面条记录 | 行动仍待反馈；餐食不作为执行完成证明 | M04、M07B 已覆盖 |
| 业务提交后响应丢失，重复点击确认 | 原操作键和摘要返回原回执；不会生成第二份记录 | M06 已覆盖；实现需改造 GAP-01 |
| 业务已写但任务更新抛错 | 同事务整体回滚；不会出现“记录存在、任务仍待确认”的成功结果 | ADR-05、M06；事务外外调不占锁 |
| 两个页面使用同版本修正记录 | 只有一个命令成功；另一个提示重载；新意图使用新键 | 事务版本检查与回执契约已覆盖 |
| 修改已确认计划后打开旧清单 | 旧清单 stale；差异预览后重建；历史餐食、待反馈行动独立 | M05、ADR-04 已覆盖 |
| 周日执行，周二补反馈为完成 | 北极星回填执行日期所属周；反馈覆盖率回填窗口结束所属周 | 复核 SRS 第 8 页，明确两种周归属 |
| 周内已反馈，但行动窗口下周才结束 | 本周北极星按执行日判定；本周反馈率 E 不包含该行动 | 第 04 章回顾定义已覆盖 |
| 同餐记录面条、饮料两条 | 覆盖餐次分子只加一；不会以记录条数使覆盖率超 100% | 分子去重并限定确认槽位；额外餐次单列 |
| 撤销历史授权后恢复旧任务 | 重新检查当前授权，历史候选失效或重算；不沿旧快照继续读取 | M06、分层记忆规则已覆盖 |
| 删除后用旧键请求已提交结果 | 先验权；回执最小化或清除；不重新暴露被删业务内容 | 第 04 章恢复协议已覆盖 |

## 下一轮验证重点

静态审查已暴露的实现差距列为 GAP-01 至 GAP-10。第三部分 需要将上述场景转成可复现的契约、故障注入与用户任务验证。下一阶段先完成界面/流程设计，使“待核对、草案、待反馈、未知、版本失效”等状态在用户操作中清晰可见。
