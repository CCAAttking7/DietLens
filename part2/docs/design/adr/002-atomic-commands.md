# ADR-002 命令使用同库原子提交与持久回执

状态：用户在P3成果展示后要求“继续”，本决策沿用进入P4。日期：2026-11-17。

## 背景与决定

计划槽位替换、行动采纳和记餐需要在响应丢失或重复点击后得到唯一可查结果。每条写命令携带操作标识、请求摘要、预期对象版本与确认草稿版本。短事务内复核当前授权，检查版本，提交业务事实、任务进度、审计事件及回执；任一失败整体回滚。同一用户和操作标识设唯一约束，重复请求还需比较摘要。

同一用户的处理控制先锁定，再按固定顺序访问业务对象。模型和食品资料查询在写事务外完成，提交前重新核对其绑定版本。授权撤回与删除也遵循同一锁顺序。

## 备选与影响

先写业务再写回执会出现已提交却无法识别重复。只在进程中去重不能跨重启。全事件溯源或消息队列会扩大当前恢复范围，暂不采用。用户级写串行降低同用户并行写吞吐，但简化授权与跨对象不变量；不同用户可并行。

## 验证与重审

后续验证双击、并发同键、同键异内容、版本冲突、事务中断、提交成功但响应丢失、撤回与写入竞争。逐项断言业务与回执均为零份或一份。关联FR-010、FR-011、FR-013、FR-014、FR-017、FR-020；准确需求以[正式规格](../../../specs/001-dietlens-design/spec.md)为准。HTTP错误载荷留P5。
